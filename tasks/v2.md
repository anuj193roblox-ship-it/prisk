# prisk v2: plan and tasks

Implements [SPEC-v2.md](../SPEC-v2.md). Branch: `v2`.

## Order

```
git readers (diff pkg)  ──┐
config parser           ──┼──→  risk (pure checks)  ──→  CLI wiring  ──→  README, PR
gittest dated commits   ──┘
```

Readers and the config parser don't depend on each other. `risk` only needs their data types.
The one risky step is task 5, the `risk.Score` refactor: it changes every v1 test call. It's done
*before* the new checks, with no behaviour change, so the v1 tests prove nothing broke.

## Checkpoints

- **After task 5:** v1 behaviour unchanged, all v1 tests green on the new `Input` shape.
- **After task 8:** criteria 1–9 pass. Stop, show you, then do task 9 (README, PR).

## Risks

| Risk | Mitigation |
|---|---|
| `git log` on a big repo is slow | Cap 5,000 commits + 365 days; timed on `headroom` (criterion 10). |
| Tests depend on today's date | Windows are measured from the base branch's newest commit, and tests set commit dates explicitly. |
| Config read from the wrong side (PR head) | End-to-end test: config only on the PR branch must have no effect (criterion 7). |
| Moving `sensitiveDirs` into config breaks v1 matching | Same `isSensitive` logic, just given the list; v1 table tests kept. |
